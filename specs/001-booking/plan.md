# แผนพัฒนา Feature: จองคิวตรวจสุขภาพ (Booking)

## 1. สรุปแนวทาง

1. ผู้รับบริการที่ผ่านการยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ
2. ระบบแสดงช่วงเวลาว่างภายใน 30 วัน พร้อมจำนวนที่นั่งคงเหลือของแต่ละช่วงเวลา
3. ระบบตรวจสอบคิวเดิมของผู้รับบริการ และคำนวณช่วงเวลาใหม่เมื่อเปลี่ยนแพ็กเกจ
4. เมื่อยืนยันสำเร็จ ระบบบันทึกการจอง ออกหมายเลขคิว และลดจำนวนที่นั่ง
5. ระบบส่งคำขอแจ้งเตือนแบบ asynchronous พร้อมรองรับ retry ตาม NFR-REL-02

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้าจอเลือกแพ็กเกจ/วัน/ช่วงเวลาและหน้าผลการจอง |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้าง API สำหรับการค้นหาและยืนยันการจอง |
| MySQL | CON-TECH-01 | ใช้จัดเก็บการจอง ที่นั่ง หมายเลขคิว งานส่งซ้ำ และ audit log |
| TLS 1.2 ขึ้นไป | NFR-SEC-01 | ใช้เข้ารหัสการรับส่งข้อมูลระหว่างผู้ใช้กับระบบ |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Booking` | `id`, `hn`, `package_id`, `service_date`, `time_slot_id`, `queue_number`, `status`, `created_at` | FR-BKG-02, FR-BKG-04, FR-BKG-05 |
| `TimeSlot` | `id`, `service_date`, `start_time`, `end_time`, `capacity`, `remaining_seats`, `package_id` | FR-BKG-01, FR-BKG-03, FR-BKG-06 |
| `NotificationJob` | `id`, `booking_id`, `channel`, `status`, `attempt_count`, `next_attempt_at`, `last_error` | FR-BKG-04, FR-BKG-05, NFR-REL-02, IF-NOT-01 |
| `AuditLog` | `id`, `accessor_id`, `accessed_at`, `hn`, `action` | DOM-PDPA-01, AC-BKG-06 |
| `PatientReference` | `hn`, ข้อมูลอ้างอิงที่ได้รับจาก HIS ตามจำเป็น | IF-HIS-01 |

- ตาราง `Booking` ต้องไม่มีฟิลด์เลขบัตรประชาชนตาม IF-HIS-01
- ข้อมูลโควตา/ที่นั่งของ `TimeSlot` อ่านจากข้อมูลที่ UC-09 จัดเตรียมไว้ตาม ASM-01 ไม่สร้างหน้าจัดการโควตาใน feature นี้
- การยืนยันการจองต้องใช้ transaction และ row lock หรือกลไกเทียบเท่าที่ระดับฐานข้อมูล เพื่อป้องกันการจองซ้อนตาม ASM-07
- การสร้างหมายเลขคิวต้องเริ่มใหม่เวลา 00:00 และนับต่อเนื่องภายในวันเดียวกันตาม ASM-03 และใช้เขตเวลา Asia/Bangkok ตาม ASM-02
- การค้นหา 3 ช่วงเวลาใกล้เคียงต้องพิจารณาช่วงเวลาก่อนหน้าและถัดไป รวมถึงวันก่อนหน้าและวันถัดไปตามลำดับความใกล้เคียงตาม ASM-05

## 4. API / หน้าจอ

| รายการ | Input หลัก | Output หลัก | รองรับ |
|---|---|---|---|
| `GET /booking/availability` | `package_id`, ช่วงวันที่ไม่เกิน 30 วัน | วัน ช่วงเวลา และ `remaining_seats` | FR-BKG-01 |
| `GET /booking/availability` เมื่อเปลี่ยนแพ็กเกจ | `package_id` ใหม่, ช่วงวันที่ | ช่วงเวลาว่างที่คำนวณใหม่ | FR-BKG-06 |
| `POST /booking/confirm` | ผลยืนยันตัวตน, `package_id`, `service_date`, `time_slot_id` | `booking_id`, `queue_number`, ที่นั่งคงเหลือ | FR-BKG-04, AC-BKG-01 |
| `POST /booking/confirm` กรณีมีคิวเดิม | ข้อมูลการจองและ HN จาก identity context | ข้อผิดพลาดพร้อม `queue_number` เดิม | FR-BKG-02, AC-BKG-02 |
| `POST /booking/confirm` กรณีช่วงเวลาเต็ม | ข้อมูลการจองและ HN จาก identity context | แจ้งช่วงเวลาเต็มและ 3 ตัวเลือกใกล้เคียงจากช่วงเวลาก่อนหน้า/ถัดไปและวันก่อนหน้า/ถัดไป | FR-BKG-03, AC-BKG-03 |
| หน้าจอ `BookingForm` | แพ็กเกจ วัน ช่วงเวลา | ข้อมูลที่เลือกและจำนวนที่นั่ง | FR-BKG-01, FR-BKG-06 |
| หน้าจอ `BookingResult` | ผลการยืนยัน | หมายเลขคิวและสถานะการจอง | FR-BKG-04, FR-BKG-05 |

ทุก endpoint ที่เข้าถึงข้อมูลผู้รับบริการต้องตรวจผลยืนยันตัวตนจาก IF-IDP-01 และบันทึก `AuditLog` ตาม DOM-PDPA-01

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | ใช้ MySQL สำหรับ entity ทั้งหมดในหัวข้อ 3 | ใช้แล้ว |
| DOM-PDPA-01 | สร้าง `AuditLog` และบันทึกผู้เข้าถึง เวลา และ HN ทุกครั้งที่เข้าถึงข้อมูลผู้รับบริการ | ใช้แล้ว |
| IF-IDP-01 | ตรวจผลยืนยันตัวตนก่อนเรียก API ที่เข้าถึงข้อมูลผู้รับบริการในหัวข้อ 4 | ใช้แล้ว |
| IF-HIS-01 | ใช้ `PatientReference.hn` เป็นตัวอ้างอิงภายใน และห้ามเก็บเลขบัตรประชาชนใน `Booking` | ใช้แล้ว |
| IF-NOT-01 | สร้าง `NotificationJob` และส่งคำขอแบบ asynchronous โดยไม่ให้การยืนยันรอผลส่งข้อความ | ใช้แล้ว |

## 7. ลำดับงาน

1. กำหนด schema ของ `Booking`, `TimeSlot`, `NotificationJob` และ `AuditLog` โดยไม่เก็บเลขบัตรประชาชน (FR-BKG-01, FR-BKG-04, DOM-PDPA-01, IF-HIS-01)
2. สร้างการตรวจผลยืนยันตัวตนและการอ้างอิง HN จาก HIS (IF-IDP-01, IF-HIS-01)
3. สร้าง API และหน้าจอค้นหาช่วงเวลาว่างภายใน 30 วัน (FR-BKG-01, AC-BKG-05)
4. เพิ่มการคำนวณช่วงเวลาว่างใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-06)
5. เพิ่มการตรวจคิวเดิมและการแสดงหมายเลขคิวเดิม (FR-BKG-02, AC-BKG-02)
6. สร้าง flow ยืนยันการจอง ออกหมายเลขคิว และลดที่นั่ง (FR-BKG-04, AC-BKG-01)
7. เพิ่ม transaction และ row lock เพื่อป้องกันการจองซ้อนเมื่อยืนยันพร้อมกัน (FR-BKG-03, FR-BKG-04, AC-BKG-03)
8. เพิ่มการแจ้งช่วงเวลาเต็มและตัวเลือกใกล้เคียง โดยพิจารณาช่วงเวลาก่อนหน้า/ถัดไปและวันก่อนหน้า/ถัดไป (FR-BKG-03, AC-BKG-03)
9. สร้าง asynchronous notification job และ retry ตาม NFR-REL-02 (FR-BKG-05, AC-BKG-04)
10. ทดสอบ audit log, performance และ acceptance criteria ทั้งหมด (AC-BKG-01 ถึง AC-BKG-06)
